# 离线数字化验收与付款台

纯前端离线应用（无网络、无后端、无构建依赖），用于老胶片数字化外包业务的**验收与付款管控**：
管理胶片卷、扫描批次、外包商、合同、质检缺陷、付款节点，驱动批次验收流转，并在多级审批下安全付款。

## 运行

直接用浏览器打开 `index.html` 即可；或在本目录：

```bash
python3 -m http.server 8080   # 然后访问 http://localhost:8080
```

所有数据保存在浏览器 `localStorage`（键 `digitdesk:data:v1`），完全离线。

## 测试（无需浏览器）

```bash
npm test
# 或
node test/core.test.js      # 业务规则：80 个断言
node test/walkthrough.js    # 点击级走查：131 个断言，覆盖全部规定场景
```

`test/dom-shim.js` 是自包含的极简 DOM（HTML 解析/选择器/事件冒泡/FormData），
在 Node 中加载**真实的 `js/ui.js`** 驱动点击，不是把逻辑抄一遍的假测试。

## 功能与管控规则

### 实体
- **外包商 / 合同 / 胶片卷 / 扫描批次 / 质检缺陷 / 付款节点 / 付款单**，编号全局唯一。
- 合同：预算、单帧价、保证金扣留比例、最低验收比例、有效期、所属外包商。
- 胶片卷：总画幅、接续关系（可形成链条，禁止成环）。
- 付款节点：金额上限、计划日期、前置节点（前置未付款不得付款，禁止成环）。

### 批次流转
`待扫描 → 验收 → 通过`；验收中可 `→ 返工 → 验收`；任何状态可 `冻结/解冻`（仅项目经理/管理员）。
非法流转被拒绝。验收时登记**合格画幅数**（可部分通过，按合格画幅 × 单帧价计价）与缺陷。

### 关键缺陷红线
缺陷分 `关键 / 主要 / 一般`，状态 `待整改 → 已返工待复验 → 闭环`。
**存在未闭环关键缺陷的批次：不能判通过、不能被任何付款单选入**；付款前还会做终检
（批准后若又冒出关键缺陷，付款照样拦下）。

### 付款约束（提交、审批、付款三个时刻都校验）
- 合同预算（在途+已付+本单不得超预算）；
- 付款节点额度与前置节点；
- 合同最低验收比例；
- 保证金按合同比例扣留，扣款逐条登记，`应付 = 合格画幅产值 − 扣款 − 保证金扣留`；
- **重复付款**：同一批次不能重复进入在途/已付款单；
- 只有「通过」、无未闭环关键缺陷、合格画幅 > 0 的批次可计入。

### 多级审批与职责分离
金额决定审批链：≤¥8,000 项目经理单签；≤¥100,000 加财务复核；更高再加分管领导批准。
必须**按级别顺序签、不能越级、不能同级别重复签、不能自审**；管理员不参与审批、不能直接付款；
财务确认付款时自动生成不重复流水号。角色另有发起额度（质检员不能发起付款，项目经理发起上限 50 万）。

### 审计 / 撤销重做 / 版本
- 所有成功动作与**所有被拒绝动作**都写操作审计（人、角色、时间、对象、原因），审计只能在系统内产生，不能导入。
- 成功写操作可**撤销/重做**；每 5 次写自动打版本快照（保留 20 个），可手动打点、可**回滚**
  （回滚前自动备份当前状态，因此回滚本身也可再回滚）。

### 双页竞争
- 记录级**编辑锁**（30 秒租约 + 心跳）：两个标签页同时验收同批次/编辑同付款单时，第二页被明确拦下。
- 跨页提交用 `BroadcastChannel`（storage 事件兜底）广播；动作在对方页面重放，
  互斥操作（如两页同时提交同一批次的付款）判为冲突：先提交者生效，后提交页自动加载权威数据并提示，**绝不重复付款**。

### 刷新恢复
成功动作即时落盘；付款单编辑内容实时存为草稿，刷新/重开后在「导入导出」页或新建付款单时恢复。

### 导入（整包校验，任一错误整体拒绝，零记录落库）
JSON 包只允许基础档案（付款/审批/审计等字段属**越权记录**，直接拒绝）。拦截：
- 重复编号（包内重复 / 跨类型撞号；同类型同编号按更新处理）；
- 循环引用（胶片卷接续链、付款节点前置关系）；
- 非法日期（含 2026-02-29 这类假日期）、非法金额（「壹万」「12abc」）、负数、比例越界；
- 缺失/悬空引用、画幅超过胶片卷总量；
- **伪装缩略图**：只接受 PNG/JPEG/GIF/WEBP，先查 MIME 再查文件魔数，
  声称 PNG 实为 `<svg><script>` 的文件被识别拒绝。
导入页内置「合法样例」和一个同时触发全部拦截类型的「问题样例」。

## 代码结构

| 文件 | 职责 |
| --- | --- |
| `js/core.js` | 纯业务规则（reducer、状态机、付款/审批校验、导入校验、缩略图魔数），无 DOM，可在 Node 直接测 |
| `js/store.js` | localStorage 持久化、撤销重做、版本快照/回滚、跨页并发与编辑锁、草稿 |
| `js/ui.js` | 视图渲染与控制器，所有写操作都走 `store.commit` |
| `test/core.test.js` | 规则层单测 |
| `test/walkthrough.js` | 正常验收、部分通过、关键缺陷、超付、越权、双页竞争、回滚、异常导入、伪装缩略图、刷新恢复走查 |
